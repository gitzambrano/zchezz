# v5.07 NNUE experiment status — 2026-09-15

This file is the canonical short ledger for the current v5.07 NNUE investigation. Do not promote a candidate from a small screen alone.

## Baseline

- NNU4 family baseline: `v5.06`.
- Current repository `main` at the time of this note: `fba9dfe73d677eb7230d5e2686d88540acb9030e` (`v3.30` TT move-legality release). The 3.x and 5.x families must be evaluated separately; a v5 successor is gated directly against v5.06.

## Root-probe teaching

The explicit child root-probe pipeline is operational and useful as an experimental teacher. It enumerates legal children, evaluates them cheaply, refines selected children with search, and produces policy/ranking labels without depending on MultiPV behavior.

The clean v5.06-rootprobe experiment produced three candidates from a 4,000-position mostly-on-policy corpus (~99.7k legal moves, ~7.47 refined moves/position):

- `b0`: policy/ranking only. Initial 64-game screen vs v5.06: 30W/19D/15L, 61.72%, +82.97 Elo, paired bootstrap CI95 [+27.20, +143.33].
- `bv10`: +small self-search value: 17W/24D/23L, 45.31%, -32.67 Elo.
- `b15`: +light Stockfish-19 reference: 14W/28D/22L, 43.75%, -43.66 Elo.

The large independent gate invalidated the `b0` screen:

- 400 games / 200 opening pairs, common seed with disjoint offsets 0/50/100/150.
- `b0` vs v5.06: **112W/159D/129L**, score **47.875%**, **-14.77 Elo**.
- Paired-bootstrap CI95: **[-40.13, +10.43] Elo**.
- Status: **NOT CONFIRMED / rejected as a promotion candidate**.

Conclusion: the original +83 Elo screen was a false positive. Root-probe remains a valid teacher mechanism, but this training objective/configuration did not produce a robust stronger NNU4.

## Layer-scope ablation

A shared v5.06 root-probe corpus was used to train L3-only, L2+L3, and all-layer variants. In all three cases the validation objective selected **best_epoch = 0**. Therefore no learned update beat the initial v5.06 weights according to the trainer's own objective.

48-game screens on identical openings were:

- control `b0`: 12W/19D/17L, -36.32 Elo.
- L3: 16W/20D/12L, +29.02 Elo.
- L2+L3: 17W/17D/14L, +21.74 Elo.
- all layers: 13W/24D/11L, +14.48 Elo.

Because the selected checkpoint was epoch 0, these positive short-screen numbers are not evidence of learned strength. They are further evidence that 48–64 game screens can fluctuate by several tens of Elo in this setup.

## Adaptive deep root-probe

Adaptive two-stage teaching used 4,000 positions, ~99.3k legal moves, ~10.69 searched moves/position, shallow 750-node probes and selective 8,000-node refinement.

The trainer again selected **best_epoch = 0**. Screen results:

- `b0` control vs v5.06: 14W/20D/14L = 50.0%, 0 Elo.
- adaptive vs v5.06: 11W/20D/17L = 43.75%, -43.66 Elo.
- adaptive vs `b0`: 15W/16D/17L = 47.92%, -14.48 Elo.

Status: rejected. Spending more teacher search did not solve the objective/search-coupling problem.

## Established conclusions

1. Do not use a 48–64 game screen as promotion evidence. It is only a triage signal.
2. Use paired openings and paired-bootstrap confidence intervals.
3. Robust gates should use one deterministic shuffled opening order with disjoint offsets across shards.
4. Lower static/teacher loss or stronger teacher labels do not imply higher engine Elo.
5. Wider NNU4 alone previously failed; stronger Stockfish value teaching alone previously failed.
6. The main unresolved issue is evaluator/search coupling and training objective, not basic NNU4 throughput.
7. v3.28's extra global/relational feature channel remains architecturally interesting, but destructive un-retrained ablations cannot be interpreted as standalone feature Elo.

## Next experiments, in order

1. Treat **v5.06 as the only valid v5 baseline** until a candidate passes a large gate.
2. Change the training target/objective rather than merely increasing teacher depth: search-outcome calibrated value, pairwise/root ordering with a validation metric aligned to actual root decisions, and stricter trust-region control.
3. Test a low-risk **NNU4+ global auxiliary channel**: preserve the existing NNU4 core, add a small zero-initialized correction head using already available bitboards/global features (material/phase, passed-pawn files, king geometry). Zero initialization must reproduce v5.06 exactly before training.
4. Gate any promising candidate with at least 400 games / 200 distinct opening pairs and paired-bootstrap CI. Replicate on a second seed/opening partition before promotion.
5. Never promote a v5 candidate based on comparison with the 3.x family; direct predecessor v5.06 is mandatory.
