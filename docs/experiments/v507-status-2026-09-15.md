# v5 NNUE research ledger — updated 2026-09-16

This is the canonical short ledger for the current v5 NNUE investigation. Treat `v5.06` as the only valid v5 baseline until a candidate passes a large direct gate. Never promote from a short screen alone.

## Baselines

- v5 family baseline: **v5.06**, NNU4 HalfKP-4Bucket `2560 -> 48/perspective -> 20 -> 1`, weight SHA256 `5e6cca42f11823505edefb3ee068e0e9bb3a8576f8fb5b0b7a688736ed377150`.
- primary 3.x family on `main`: **v3.30**.
- Cross-family comparisons are diagnostic only. Any v5 successor must beat v5.06 directly.

## Root-probe teaching: valid mechanism, old objective rejected

The root-probe teacher enumerates legal children, ranks them cheaply, then searches selected children independently. It is operational and produces dense child-ordering labels.

The original clean v5.06 root-probe `b0` screen looked very strong at 64 games: **30W/19D/15L = +82.97 Elo**. A proper independent gate invalidated it:

- 400 games / 200 paired openings, disjoint opening offsets.
- `b0` vs v5.06: **112W/159D/129L**, 47.875%, **-14.77 Elo**.
- paired-bootstrap CI95: **[-40.13, +10.43] Elo**.

Layer-scope ablations and adaptive/deeper root-probe also selected **epoch 0** under the old policy/ranking/trust objective. Conclusion: root-probe itself remains useful, but the old distillation objective is not a robust strength direction.

## NNU5 / larger-network diagnosis

The frozen v5.09 NNU5 was rematerialized on v5.06 search as diagnostic v5.21, isolating the network from later search changes.

Architecture: HalfKP-8Bucket, `5120 -> 192/perspective -> 32 -> 1`, ~1.98 MB weights. Original training used 2.4M phase-balanced positions and converged offline.

Fixed-node H2H removes throughput as the main explanation for its weakness:

- v5.21 vs v5.06 at 200k nodes/move: **15W/2D/23L = -70.44 Elo**.
- v5.21 vs v3.28 at 200k nodes/move: **12W/1D/27L = -136.97 Elo**.

Status: **capacity scaling rejected in the present training formulation**. More parameters/data and slightly better teacher move agreement did not translate into alpha-beta strength.

## Static-evaluation calibration diagnostic (v5.22)

On 480 independent positions against pinned Stockfish 19 at 16,384 nodes:

- v5.06: MAE **162.12 cp**, RMSE **273.51**, Pearson **0.8246**, near-even MAE **87.23 cp**.
- v3.28: MAE **141.21 cp**, RMSE **249.05**, Pearson **0.8779**, near-even MAE **63.03 cp**.

A single affine rescale does not close the gap. v5.06 phase slopes also vary strongly by material. Conclusion: the v5.06 weakness is not merely one output-scale constant; useful evaluation structure/ranking is missing or poorly learned.

## Historical QAT/runtime mismatch (v5.23)

Historical NNU4/NNU5 QAT did not reproduce the C runtime's discrete `>>8` activation equations. Direct measurement on real v5.06 weights over 3,000 positions found:

- L1 code mismatch: **32.45%**.
- L2 code mismatch: **34.54%**.
- score MAE training-forward vs runtime: **18.97 cp**.
- RMSE **23.36 cp**, p95 **44.45 cp**, max **67.34 cp**.
- **66.5%** of positions differed by more than 10 cp.

This mismatch exists in v5.06 too, so it does not by itself explain the NNU5 regression. It nevertheless means historical training optimized a materially different evaluator from the one used by search.

## Runtime-exact QAT causal test (v5.24) — closed

Branch: `exp/v524-exact-qat-rootprobe`, run `35052864357`.

`ExactRuntimeNNUE` reproduced the C evaluator with **0 mismatches in 256 positions** before training and **0/128** after export. The runtime-exact implementation is therefore validated infrastructure.

Repeating the old b0 root-probe objective with exact QAT still selected **best_epoch = 0**. No trained epoch beat the original v5.06 weights under that objective. The exported checkpoint is effectively v5.06.

Its 96-game screen was **29W/43D/24L = +18.11 Elo**, CI95 **[-32.67, +69.68]**, but because best_epoch=0 this is explicitly a noise/control result, not learned strength.

Conclusion: **keep runtime-exact QAT, reject the old b0 objective**.

## Global-to-L2 side channel (GLB2) — closed/rejected

Branch: `exp/v507-global-l2`, run `35046251975`.

Design: freeze v5.06 NNU4 and add a 31->20 global projection into L2 (~620 int8 weights). Zero-init evaluator equivalence passed.

All three feature sets selected **best_epoch = 0**, so no learned projection survived validation. The additional runtime path nevertheless reduced bench throughput from about **2.28M NPS to 1.71-1.72M NPS** (~25% penalty).

96-game screens, therefore essentially v5.06 plus overhead:

- all-global: **22W/37D/37L**, **-54.74 Elo**, CI95 [-108.33, -3.62].
- aggregate/material: **30W/32D/34L**, **-14.48 Elo**, CI95 [-69.68, +39.99].
- relational: **19W/39D/38L**, **-69.68 Elo**, CI95 [-124.50, -18.11].

Status: **rejected**. Do not gate or promote any GLB2 variant.

## Centered search-delta microcorrection (v5.25) — active

Branch: `exp/v525-centered-delta`.
Workflow run: **`35138319132`**.

This changes the learning target rather than the architecture. It keeps runtime-exact QAT and v5.06 as the frozen reference. For each parent and child:

`raw_delta_i = root_probe_search_cp_i - v506_static_cp_i`

Then remove the per-parent mean and train only a conservative fraction of the residual:

`target_i = gain * clip(raw_delta_i - mean(raw_delta), +/-96 cp)`

The student's own per-parent mean change is separately anchored toward zero. Therefore absolute teacher calibration is intentionally discarded; the network only learns local search-informed correction shape/order.

Three variants share exactly the same 5,000-position root-probe corpus and are trained/screened in parallel:

- `d25`: 25% target gain, train L2+L3.
- `d50`: 50% target gain, train L2+L3.
- `d25l3`: 25% target gain, train only L3.

A variant that selects epoch 0 skips H2H automatically. A learned variant receives perft/UCI/runtime-exact parity, NPS diagnostic and a 96-game paired triage vs v5.06. A positive short screen is not promotable; it must then pass a 400-game/200-pair gate with disjoint opening partitions and paired bootstrap.

## Established experimental rules

1. 48-96 game H2H is triage only; it can fluctuate by many tens of Elo.
2. Epoch 0 must always be an eligible checkpoint. A positive H2H from an epoch-0-equivalent candidate is noise, not learning.
3. Use paired openings and paired-bootstrap confidence intervals.
4. Robust gates use one deterministic shuffled opening order with disjoint offsets across shards.
5. Lower static loss, lower teacher MAE, larger networks and stronger teachers do **not** imply higher Elo.
6. Runtime-exact QAT is now required for new NNU4/NNU5 training work.
7. Avoid adding runtime architecture cost unless a non-zero learned signal is demonstrated first.
8. Do not mix architecture, teacher, search and objective changes in one causal experiment.
9. No v5 candidate is promoted without a direct large gate against v5.06.

## Current direction

Finish v5.25. If one centered-delta variant learns (`best_epoch > 0`) and has a meaningful positive triage, run a 400-game direct gate immediately. If all variants fail, retain exact-QAT infrastructure and move to an even more explicit pairwise/search-utility residual objective rather than returning to absolute Stockfish CP imitation or larger networks.
